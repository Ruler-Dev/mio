# Mio engineering and adaptive-effort checkpoint — 2026-07-18

## Evidence status

This checkpoint records verified engineering and calibration observations. It
does not report a held-out adaptive-effort evaluation, a Qwen 3.6 27B
replication, or a throughput comparison. Raw prompts, completions, hidden test
sources, and per-task hidden labels are intentionally absent.

The results support four limited conclusions:

1. Mio's native coding agent can now preserve a multi-step tool transcript and
   finish a real edit/test task instead of entering a read loop.
2. The pinned HumanEval verifier has source-bound 164/164 canonical-solution
   parity, and the version-two benchmark protocol checks that evidence before
   any calibration or evaluation.
3. The present 32-task calibration split cannot support the stratified Markov
   transition gate. FP32 uncertainty renormalization removes the observed
   exact-zero collapse, but does not create sufficient transition support.
4. A source-free paired ablation found that FP32 renormalization at stride 8
   reduced the instrumented uncertainty-scoring cost, but did not improve the
   raw ranking signal or end-to-end generation time.

No breakthrough has been demonstrated.

The agent replay repair landed at revision `29fe3ed`; the source-attested
verifier certificate is rooted at `2e0182d` and enforced by the fail-closed
gate at `cc087d1`. Both calibration runs came from the clean revision
`c0db185`, using MLX 0.32.0 and MLX-LM 0.31.3. These identifiers describe the
evidence lineage; later documentation commits do not retroactively change it.
The final paired ablation ran from clean revision `d7d4d9e` after protocol

## Agentic coding end-to-end fixture

The baseline run exercised a real local 4B target with DFlash against a small
Python coding fixture. It called `find`, then `cat` four times. After five tool
rounds it had made no edit, run no test, and produced no terminal answer. Model
time was 10.28 seconds.

The failure was a transcript-protocol error: tool results were replayed as new
user-authored XML messages. The Qwen chat template therefore did not receive
the native relationship between an assistant request and its result. The
repair now:

- replays an assistant message containing structured `tool_calls`, followed by
  matching `role=tool` messages with call IDs;
- preserves multiple calls from one assistant turn as one structured group;
- filters native tool XML from terminal output and persisted ordinary prose;
- bounds a turn to 12 model rounds and reserves the last round for a no-tool,
  evidence-based final synthesis; and
- retains independent call-count and tool-result-size bounds.

The same fixture was then run with the two prompt policies:

| Policy | Observed path | Result | Model time | Wall time |
| --- | --- | --- | ---: | ---: |
| Caveman | `read + read -> edit -> test (pass)` | 3/3 tests passed | 5.65 s | 6.28 s |
| Ponytail | Complete edit/test path | Same correct source result; tests passed | 11.47 s | 12.61 s |

These timings are descriptive. There was one task, one model/backend setup, and
one run per policy; ordering, prompt length, recovery behavior, and thermal
state were not controlled as a policy benchmark. The result verifies tool-call
round-trip behavior, not Caveman superiority, Ponytail inferiority, generalized
agent quality, or higher tokens per second.

## Hidden-verifier certification

The committed certificate is
[`../../benchmarks/results/humaneval-verifier-parity-2e0182d.json`](../../benchmarks/results/humaneval-verifier-parity-2e0182d.json).
Its exact file SHA-256 is
`1cae53e036fb5f6bffb25d02ef8f9bbdd23c77cdc4d87b2cbf38b8967beed8ea`.
All 164 pinned HumanEval canonical solutions passed, with each prepared source
checked against the canonical reference before execution.

Protocol `mio-markov-humaneval-two-phase-v2` validates the exact certificate
bytes, schema and claim, corpus and reference manifests, timeout, task rows,
and hashes of the complete transitive verifier source bundle. A missing,
non-regular, oversized, tampered, stale, or source-mismatched certificate fails
closed before calibration or evaluation begins. This establishes verifier
parity; it does not establish model accuracy or policy gain.

From a clean checkout, the public CLI can regenerate a source-free parity
report outside the worktree:

```bash
python3 -m experimental.effort.verify_humaneval_parity \
  --output /tmp/humaneval-verifier-parity.json \
  --timeout 10 \
  --quiet
```

A newly generated report is evidence for its own exact revision. It does not
silently replace the certificate pinned by the benchmark.

## Calibration-only Markov experiment

Both runs used only the fixed 32-task HumanEval calibration split. Each run
generated all 320 candidates before performing its 320 hidden evaluations, so
hidden results could not affect later generation. Both observed eight errors
among the 32 direct candidates. Hidden test sources and per-task labels were
not serialized in the report.

The committed source-free artifacts are the
[native stride-1 report](../../benchmarks/results/markov-effort-calibration-qwen3-4b-native-c0db185.json)
and the
[FP32 stride-8 report](../../benchmarks/results/markov-effort-calibration-qwen3-4b-fp32-stride8-c0db185.json).
Their SHA-256 digests are respectively
`ef23948fcbb7424ce4450307e4f45ecec29d42dabe88f8a639967ce4700971e5`
and
`a8dc8c17e576bd1f47709703c513fad370384b7b4200780754c63ecde17373b9`.

| Configuration | Direct errors | Exact-zero raw uncertainty | Observed selector transitions | Eligible/published strata | Published transition estimates |
| --- | ---: | ---: | ---: | ---: | ---: |
| Native selected-token log probabilities, stride 1 | 8/32 | 13/32 | 16 | 0 | 0 |
| FP32 full-vocabulary renormalization, stride 8 | 8/32 | 0/32 | 5 | 0 | 0 |

The native calculation collapsed 13 observations to exactly zero uncertainty.
FP32 full-vocabulary renormalization restored numerical dynamic range, but its
public selector produced only five transition observations instead of 16.
Neither configuration met the minimum eight independent task clusters in an
eligible stratum, so the fail-closed fitter published no transition estimate.

This is a negative calibration result, not evidence that FP32 changes coding
accuracy: direct correctness was identical, and the experiment was not
designed or powered to compare end-to-end quality. It also cannot support a
prefill, decode, latency, or tokens-per-second claim.

The two implemented calibration invocations differ only in the uncertainty
options shown below. They require a clean Git tree, the pinned verifier
certificate, and the exact model contents.

```bash

python3 -m experimental.effort.bench_markov_humaneval calibrate \
  --model "$MODEL" \
  --model-revision "$MODEL_REVISION" \
  --output /tmp/mio-markov-calibration-native.json \
  --initial-max-output-tokens 256 \
  --min-task-clusters 8 \
  --bootstrap-resamples 10000 \
  --seed 20260718 \
  --validator-timeout 10 \

python3 -m experimental.effort.bench_markov_humaneval calibrate \
```

## Paired uncertainty-scoring ablation

The final v2 artifact is
[`paired-uncertainty-qwen3-4b-d7d4d9e-v2.json`](../../benchmarks/results/paired-uncertainty-qwen3-4b-d7d4d9e-v2.json),
with SHA-256
`1257f8c43ddd9b7877295caa691b2150178fd6d6546806715c3f5278f4975770`.
It ran on the same 32 calibration tasks and the exact content-bound 4B model.
The loader used a private read-only snapshot whose nine fingerprinted files
totalled 4,290,106,214 bytes; the snapshot and original identity were checked
before loading, after eager loading, and after the experiment.

The source-free run can be reproduced from the exact clean revision with:

```bash
python3 -m experimental.effort.bench_uncertainty_humaneval \
  --model /absolute/path/to/Qwen3-4B-8bit \
  --model-revision local-sha256-v1:daee7cf817887ab096be809ba598f9811376a225a95358c6567c846446fc6902 \
  --output /tmp/mio-paired-uncertainty.json \
  --max-output-tokens 256 \
  --seed 20260718
```

Generation order was counterbalanced, 16 tasks per condition order. All 64
candidates were generated before hidden verification. Every pair matched on
decoded-text hash, token-ID hash, token count, and finish reason. The identical
output was then verified once per task, and that one immutable outcome was
shared by both ranking signals: 32/32 decode-identical pairs, 24 passes and
eight errors. The report contains aggregates and high-entropy commitments, not
prompts, completions, hidden tests, or per-task labels.

| Timing scope | Native stride 1 | FP32 renormalized stride 8 | FP32 minus native |
| --- | ---: | ---: | ---: |
| Instrumented uncertainty scoring | 0.249221 s | 0.050064 s | -79.912% (native/FP32 ratio: 4.978x) |
| Adapter generation | 28.145343 s | 28.188442 s | +0.153% |
| Prefill throughput | 939.985 tok/s | 940.719 tok/s | +0.078% |
| Decode throughput | 93.851 tok/s | 93.658 tok/s | -0.206% |

The scoring timer is inside adapter generation and must not be added to it.
The 79.912% observation applies to the combined FP32-plus-stride-8 condition;
this design does not separate renormalization from sampling one token in eight.
There were no timing replications or timing confidence intervals. Adapter
generation was descriptively 0.153% slower, so this run supports no end-to-end,
prefill, decode, or general throughput speedup claim.

The backend value is an uncalibrated raw ranking score, not a probability of
task error. The v2 report therefore excludes Brier score and reliability bins
and evaluates only AUROC and area under the risk-coverage curve (AURC).

| Raw ranking metric | Native stride 1 | FP32 renormalized stride 8 | Paired delta, FP32 - native (95% task-bootstrap CI) |
| --- | ---: | ---: | ---: |
| AUROC, higher is better | 0.695313 [0.429630, 0.925005] | 0.520833 [0.257143, 0.777778] | -0.174479 [-0.504107, 0.142857] |
| AURC, lower is better | 0.170079 [0.032874, 0.346727] | 0.224079 [0.066673, 0.431641] | +0.053999 [-0.079673, 0.224869] |

The 10,000-resample paired task bootstrap produced 9,999 class-valid AUROC
samples. Both paired intervals cross zero, while both point estimates favor
native stride-1 scoring. With only 32 tasks and eight errors, the evidence is
negative/inconclusive: FP32 stride 8 is not promoted as Mio's uncertainty
router, and the held-out split remains sealed.

## Decision and next experiments

The held-out 132-task split remains sealed because the calibration protocol
produced zero eligible transition strata. Opening it now would turn an
exploratory iteration into an invalid confirmatory test.

The next sequence is:

1. Run a preregistered 2x2 calibration-only ablation separating numeric
   precision (native versus FP32 renormalization) from scoring stride (1 versus
   8). The completed joint comparison cannot attribute its scoring-time change
   to either factor.
2. If a ranking signal survives, reduce fragmentation with preregistered
   hierarchical pooling: pool quality evidence only across scientifically
   defensible action or trigger groups while retaining tier-specific cost
   envelopes and task as the independent unit.
3. Add an external calibration corpus rather than repeatedly tuning against
   HumanEval's small split. Freeze all thresholds, identities, exclusions, and
   multiplicity corrections before evaluation.
4. Only after those gates pass, commit a new preregistration and run the sealed
   held-out comparison. Qwen 3.6 27B MLX and an independent benchmark family
   remain required before any breakthrough claim.

Until then, the supported result is an agent-loop correctness repair plus a
fail-closed research harness with an inconclusive adaptive-effort calibration.
